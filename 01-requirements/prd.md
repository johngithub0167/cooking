## 1. 项目背景与目标

### 1.1 背景

家庭日常吃饭最大的决策成本是「今天吃什么」。常见痛点：

1. 每天临时想菜，耗时且容易纠结；
2. 常做的菜反复出现，缺少变化；
3. 想不起来家里能做哪些菜，也没有统一的菜品库；
4. 做完之后没有记录，下次依然重新想。

### 1.2 目标

把「今天吃什么」变成一个可操作、可积累的流程：**推荐 → 点菜 → 生成菜单 → 沉淀历史**。

### 1.3 成功衡量

- 家庭成员每天打开首页即可看到推荐菜单，1 分钟内完成点菜提交；
- 菜品库由管理员自助维护，新增菜品无需开发介入；
- 可回溯最近 30 天的点菜记录。

## 2. 目标用户与角色

| 角色 | 使用场景 | 端 | 权限 |
| --- | --- | --- | --- |
| 家庭成员 | 浏览菜品、看推荐、点菜、查看历史菜单 | C 端（移动端 H5 网页，Vue 2 + Vant） | **免登录**，打开即用，可查看全部上架菜品，可提交菜单 |

## 3. 核心业务流程

### 3.1 主流程：今日点菜

```text
打开首页
  ↓
看到「今日推荐菜单」（默认 4 个菜）
  ↓
不满意 → 点「换一批」重新推荐
  或 → 去「总菜单」按分类/关键词筛选，自己挑
  ↓
把想吃的菜加入「今日菜单」（总菜单里也能直接减掉已加的菜）
  ↓
进入「今日菜单」页：调整数量、删除、清空
  ↓
点「就吃这些」提交
  ↓
生成一条菜单记录，写入历史
  ↓
页面展示提交成功，可查看历史
```

### 3.2 后台流程：维护菜品库

```text
管理员登录后台
  ↓
分类管理：新增/编辑分类（如 荤菜、素菜、汤、主食）
  ↓
菜品管理：新增菜品 → 填名称、选分类、上传图片、写描述、填食材
  ↓
设置上架状态与排序
  ↓
菜品出现在 C 端列表与推荐池
  ↓
在点菜记录中查看家庭近期点了什么
```

### 3.3 推荐逻辑（已确认，规则推荐）

1. 候选池：状态为「上架」且未删除的菜品；
2. 排除最近 7 天已被点过的菜品（排除后不足则逐步放宽）；
3. 分类分散：尽量覆盖不同分类，**同一分类最多 2 个**；
4. **推荐数量固定为 4 个菜**（Q-04 已确认）；
5. 点「换一批」→ 重新抽样，并排除本轮已展示过的菜品；
6. 菜品库不足 4 个时全部展示，并提示「菜品库较少，请先添加菜品」；
7. 同一天首次进入结果固定（以日期为随机种子），换一批后变化（Q-15）。

### 3.4 推荐不满意时的兜底路径（Q-14，用户明确要求）

用户如果对推荐结果不满意，必须能自己动手挑，而不只是被动「换一批」：

1. 底部导航进入「总菜单」页；
2. 按分类筛选（全部 / 荤菜 / 素菜 / 汤 / 主食 …）；
3. 按菜名或食材关键词搜索；
4. 每个菜品卡片可「加入」今日菜单；
5. 已加入的菜品在总菜单里显示为「已在菜单 · N」，可直接点「−」减少或移除；
6. 顶部提供「已选 N 道」入口，随时跳到今日菜单页做批量删除。

## 5. 功能详细说明

### 5.1 C-01 首页推荐

- 页面顶部展示「今天吃什么」标题与日期；
- 默认展示 4 张菜品卡片：图片、菜名、分类标签、一句话描述；
- 每张卡片右下角有「加入菜单」按钮；
- 页面提供「换一批」按钮（每次点击重新抽样）和「全部加入」按钮；
- 菜品库为空或不足时，展示空状态引导；
- 推荐结果随日期稳定：同一天内首次进入结果一致（后端按日期做种子），换一批后在当前会话内变化。

> 是否需要「同一天结果固定」待确认，当前按「同一天首次固定」实现。

### 5.2 C-02 / C-03 / C-04 总菜单页（全部菜品）

> 这是用户对推荐结果不满意时的主路径（Q-14），必须完整可用。

页面结构：

1. 顶部搜索框：菜名 / 食材关键词，输入防抖 300ms；
2. 分类 Tab：全部 + 后台配置的分类，切换即筛选；
3. 菜品列表：卡片式，展示图片、菜名、分类标签、一句话描述；
4. 分页：默认每页 20 条，滚动到底自动加载；
5. 空状态：无菜品时引导去后台添加。

加入与删除（关键）：

1. 每个卡片上有「加入」按钮，点击后加入今日菜单；
2. 已加入的菜品按钮变为「已在菜单 · N」，右侧出现「−」按钮；
3. 点「−」数量减 1，减到 0 即从今日菜单移除，按钮回到「加入」；
4. 页面顶部常驻「已选 N 道 · 查看菜单」入口，点击进入今日菜单页；
5. 所有加入/删除操作即时同步到今日菜单与底部悬浮栏数量。

搜索规则：

- 菜名模糊匹配；
- 食材关键词匹配（如搜「鸡蛋」返回所有含鸡蛋的菜）；
- 无结果时展示空状态与「换个词试试」提示。

### 5.3 C-06 今日菜单（点菜车）

- 底部悬浮栏显示已选数量与「查看菜单」入口；
- 菜单页逐条展示已选菜品：图片、名称、数量加减、删除；
- 提供「清空」按钮（二次确认）；
- 已选菜品重复添加时数量 +1，不产生重复行；
- 页面数据本地持久化（localStorage），刷新不丢失，提交成功后清空。

### 5.4 C-07 提交菜单

- 点击「就吃这些」提交，提交时校验至少 1 个菜；
- 提交按钮防重复点击；
- 提交成功后跳转成功页，展示菜名清单与日期，可查看历史；
- 同一天允许提交多次（追加记录，不覆盖），每条记录独立。

### 5.5 C-08 历史菜单

- 按日期倒序分组展示；
- 每条记录展示日期、菜品数量、前 3 个菜名；
- 点击展开查看完整菜品列表；
- 支持下拉加载更多（默认每次 20 条）。

### 5.6 A-02 菜品管理

- 列表字段：缩略图、菜名、分类、状态、排序、更新时间、操作；
- 支持按分类筛选、按名称搜索、按上架状态筛选；
- 新增/编辑使用抽屉或表单页，必填项：名称、分类、主图；
- 删除为逻辑删除（标记 `deleted`），删除需二次确认；
- 上下架切换即时生效，下架菜品不出现在 C 端。

### 5.7 A-05 图片上传

- 支持点击上传与拖拽上传（后台）；
- 格式：jpg / png / webp；大小：≤ 5MB；
- 上传后展示缩略图预览，可删除重传；
- 前端做格式与大小预校验，后端做二次校验；
- 上传接口需要管理员鉴权。

## 6. 数据实体初步清单

> 以下为需求视角的实体清单，正式表结构由技术设计阶段在 `02-design/database-design.md` 中定义。

| 实体 | 关键字段（初步） |
| --- | --- |
| 菜品 Dish | id、名称、分类 id、主图 URL、描述、辣度、烹饪时长、状态（上架/下架）、排序值、创建时间、更新时间、删除标记 |
| 分类 Category | id、名称、排序值、启用状态、创建时间 |
| 食材 Ingredient | id、名称、创建时间 |
| 菜品-食材关联 DishIngredient | 菜品 id、食材 id、用量说明（可选） |
| 菜单记录 MenuRecord | id、日期、菜品数量、备注（可选）、创建时间 |
| 菜单明细 MenuItem | id、菜单记录 id、菜品 id、菜品名称快照、数量、图片快照 |
| 管理员 Admin | id、用户名、密码哈希、创建时间、最后登录时间 |
| 文件 File（可选） | id、原始文件名、存储路径、访问 URL、大小、上传时间 |

> 菜单明细保存菜品名称与图片快照，避免菜品改名或删除后历史记录错乱。

## 8. MVP 范围界定

MVP 目标：**打通「推荐 → 点菜 → 提交 → 记录 → 后台维护」这条最小完整链路。**

必须完成：C-01 ~ C-08、A-01 ~ A-06、S-01 ~ S-08。

已确认的技术前提：

- C 端：移动端 H5 网页，Vue 2 + Vant；
- 后台：PC Web，Vue 2 + Element UI；
- 后端：Node.js + Express；
- 数据库：MySQL；
- C 端免登录，后台需登录。

明确不做（第一版）：

- 用户注册、登录（C 端）、家庭群组、多人协作
- 支付、计价、结算、优惠
- 机器学习/个性化智能推荐
- 营养与热量计算
- 菜品做法步骤详情与视频
- 评论、评分、收藏、点赞、分享
- 消息推送与订阅通知
- 数据统计大屏、Excel 批量导入
- 多管理员与角色权限
- 国际化、多语言
